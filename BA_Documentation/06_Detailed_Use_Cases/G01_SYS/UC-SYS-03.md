# UC-SYS-03 — Đăng nhập

| Thuộc tính | Nội dung đặc tả |
|---|---|
| Mã Use Case | UC-SYS-03 |
| Tên Use Case | Đăng nhập |
| Mô tả nghiệp vụ | Chủ tài khoản chưa đăng nhập cung cấp email/mật khẩu, thêm mã MFA khi ADMIN đã bật MFA, nhận phiên và được điều hướng theo role/quyền [UI, SVC, NAV]. Không coi việc nhận phiên là đã đủ quyền mọi màn hình. |
| Phạm vi và cấp độ | Hệ thống quản lý nhà trọ; G01 — Tài khoản và an toàn truy cập; mục tiêu người dùng, AS-IS. |
| Tác nhân chính | Khách/chưa đăng nhập (A01) |
| Tác nhân phối hợp | Không áp dụng |
| Mục tiêu nghiệp vụ | Nhận phiên đúng danh tính và điều hướng theo vai trò |
| Sự kiện kích hoạt | A01 chọn Log in; với ADMIN đã bật MFA, UI yêu cầu mã sau phản hồi MFA_REQUIRED/INVALID_MFA_CODE [UI]. |
| Tiền điều kiện | User đã tồn tại, active và có passwordHash hợp lệ. ADMIN bật MFA phải có cấu hình giải mã secret khả dụng và mã chưa dùng còn hợp lệ. API login công khai; STAFF còn phải đáp ứng profile/chủ trọ active khi dùng JWT ở request bảo vệ tiếp theo, không phải điều kiện đã được kiểm trong login [SVC, MFA, JWT]. |
| Dữ liệu đầu vào và Validation | email bắt buộc IsEmail, DTO không MaxLength; service trim/lowercase. password string bắt buộc 1–128 ký tự (không áp chính sách mật khẩu mới cho login). mfaCode tùy chọn, string 6–64 ký tự; AuthApi trim và chỉ gửi khi có; khi ADMIN profile.mfaEnabled=true thì service bắt buộc mã [VAL, API, SVC]. UI chỉ kiểm email và mật khẩu không rỗng; rememberMe mặc định true nhưng _submit không truyền giá trị này, chưa có chính sách TTL theo lựa chọn [UI]. |
| Luồng thành công chính | B1 — A01 nhập email/mật khẩu trên LoginScreen và chọn đăng nhập; UI kiểm form, gửi POST /api/v1/auth/login [UI, API].<br>B2 — Hệ thống kiểm DTO và limiter 10/60 giây; chuẩn hóa email, tìm User, kiểm isActive và xác minh argon2 passwordHash [CTRL, VAL, SVC].<br>B3 — Với tài khoản không cần mã ở lần gửi này (không phải ADMIN bật MFA), hệ thống giữ mfaVerified=false rồi cấp AuthSession/RefreshToken; khóa User để kiểm active/version trước tạo phiên [SVC, SESSION].<br>B4 — Hệ thống serialize role/profile/permissions và ký JWT với sub, role, sid, ver, mfa; trả data User/token và mốc hết hạn [SESSION].<br>B5 — Repository chấp nhận role landlord/admin/tenant/staff và lưu phiên; SessionController chuyển authenticated [STORE, STATE].<br>B6 — UI chỉ chấp nhận next thuộc các trang public discovery; nếu không thì đi homeRouteForSession: landlord /dashboard; tenant /explore; staff trang đầu có quyền hoặc /settings; admin /admin/security nếu MFA required chưa verified, còn lại /admin [UI, NAV]. |
| Luồng thay thế | A1 — Tại B2, ADMIN profile.mfaEnabled=true và chưa gửi mã: hệ thống trả 401 MFA_REQUIRED, không cấp phiên; UI mở ô mã và thông báo Admin cần mã xác thực hai lớp hoặc mã khôi phục. A01 nhập mã rồi gửi lại email/mật khẩu/mã; quay B2 [UI, SVC].<br>A2 — Tại B3, ADMIN bật MFA đã gửi mã TOTP 6 chữ số hợp lệ trong bộ đếm hiện tại ±1 và lớn hơn mfaLastCounter: hệ thống lưu bộ đếm/audit trong transaction MFA, đặt mfaVerified=true rồi quay B4 [MFA, SVC].<br>A3 — Tại B3, ADMIN gửi recovery code có SHA-256 nằm trong recoveryHashes: hệ thống loại hash đó, ghi audit, đặt mfaVerified=true rồi quay B4; mã chỉ dùng một lần; không phát sinh bộ mã mới khi login [MFA].<br>A4 — Tại B6, ADMIN chưa bật MFA nhưng cấu hình yêu cầu MFA: login vẫn có thể cấp phiên mfa=false, UI chuyển /admin/security để thiết lập; chưa cho rằng đã vào Admin Console đầy đủ. Kết thúc đăng nhập, UC-ADM-07.1 là mục tiêu tiếp theo [SVC, NAV]. |
| Luồng ngoại lệ | E1 — Tại B1/B2: UI chặn trường rỗng/email sai, không gửi và không ghi; nếu gọi API với DTO sai thì 400 VALIDATION_ERROR, details theo filter; UI hiển thị message, tiếp tục sửa B1 [UI, VAL, HTTP, ERR].<br>E2 — Tại B2: không tìm thấy User, inactive hoặc mật khẩu sai, trả 401 INVALID_CREDENTIALS với Email or password is incorrect.; không cấp phiên, SessionState unauthenticated và UI hiển thị message; quay B1 [SVC, STATE, UI].<br>E3 — Tại B3/A2/A3: mã sai/đã dùng trả 401 INVALID_MFA_CODE, UI giữ ô MFA và thông báo Mã xác thực không hợp lệ hoặc đã sử dụng.; transaction MFA không cập nhật mã/bộ đếm, chưa cấp phiên; A01 nhập mã khác và gửi lại B2. Trạng thái MFA không hợp lệ trả 401 UNAUTHORIZED [MFA, UI, ERR].<br>E4 — Tại B2: quá 10/60 giây, 429 RATE_LIMITED; UI hiển thị message, không cấp phiên; kết thúc lần gửi [CTRL, RATE, ERR, UI].<br>E5 — Tại B3–B5: lỗi cấu hình khóa MFA, DB, ký JWT, parse hoặc storage; UI hiển thị ApiFailure.message hoặc Unable to sign in right now. Please try again.; SessionState unauthenticated. MFA có thể đã tiêu thụ mã trước khi lỗi cấp phiên; AuthSession/RefreshToken có thể đã commit trước lỗi ký/serialize/lưu cục bộ. Không tự khôi phục recovery code [SVC, MFA, SESSION, STORE, STATE]. |
| Hậu điều kiện thành công | Phiên được cấp/lưu và frontend authenticated; dữ liệu role/quyền dùng cho điều hướng. ADMIN dùng MFA có mfaVerified=true và đã ghi bộ đếm hoặc tiêu thụ recovery code. Không bảo đảm profile STAFF/chủ trọ active từ login vì kiểm đó nằm ở JwtStrategy cho request sau [SESSION, MFA, JWT]. |
| Bảo đảm tối thiểu khi thất bại | Lỗi credential/DTO không cấp phiên. Transaction xác minh MFA và transaction tạo session độc lập; ký JWT và lưu storage nằm ngoài transaction tạo session. Lỗi phản hồi không bảo đảm mã MFA chưa bị dùng hoặc phiên backend chưa tồn tại [SVC, MFA, SESSION, STORE]. |
| Quy tắc nghiệp vụ | BR-01 — Credential sai/không có/inactive cùng INVALID_CREDENTIALS [SVC].<br>BR-02 — Chỉ ADMIN profile.mfaEnabled=true mới bị login yêu cầu mã; mfaRequired do cấu hình không tự thay thế điều kiện này [SVC, MFA].<br>BR-03 — TOTP SHA1, chu kỳ 30 giây, 6 chữ số, chấp nhận counter−1/counter/counter+1 nhưng phải lớn hơn lastCounter; recovery code chỉ dùng khi không activate [MFA].<br>BR-04 — Cấp phiên kiểm lại active/version; mặc định refresh TTL 30 ngày, access fallback 15 phút, phụ thuộc cấu hình; không thay TTL bằng rememberMe [SESSION, UI].<br>BR-05 — Không cấp role từ input; backend serialize role thật. STAFF profile inactive vẫn có thể nhận response login nhưng JWT request tiếp bị 401 [SVC, JWT]. |
| Phân quyền và bảo mật | Actor A01 là chủ tài khoản trước xác thực; không thêm A02–A05 làm actor đăng nhập riêng. Login không @Roles/JWT. AuthSession chứa version; refresh raw chỉ trả client, backend lưu SHA-256. JWT protected requests kiểm user/session live; ADMIN không tự thừa hưởng quyền chủ trọ [CTRL, SESSION, JWT]. Không thêm include Đăng nhập vào các UC đã xác thực. |
| Kết quả đầu ra | POST mặc định HTTP 201; data {user, accessToken, refreshToken, accessTokenExpiresAt, refreshTokenExpiresAt}; user gồm quyền/profile theo role và adminMfaVerified [CTRL, SESSION]. Điều hướng là B6, không mặc định TENANT đến /tenant. |
| Quan hệ với Use Case khác | UC-ADM-07.1 tạo MFA dùng ở nhánh ADMIN; UC-SYS-05.1/05.2 quản lý phiên sau đó. UC-SYS-06/07/10 thay mật khẩu và thu hồi hiệu lực phiên. Các quan hệ trình tự/ngữ cảnh này không phải include/extend; sơ đồ giữ association A01–UC-SYS-03 [UML]. |
