# UC-SYS-07 — Đổi mật khẩu khi đang đăng nhập

| Thuộc tính | Nội dung đặc tả |
|---|---|
| Mã Use Case | UC-SYS-07 |
| Tên Use Case | Đổi mật khẩu khi đang đăng nhập |
| Mô tả nghiệp vụ | Người đang đăng nhập đổi mật khẩu bằng mật khẩu hiện tại; backend tăng sessionVersion và thu hồi refresh token, frontend dọn phiên rồi yêu cầu đăng nhập lại [SVC, STATE, UI]. |
| Phạm vi và cấp độ | Hệ thống quản lý nhà trọ; G01 — Tài khoản và an toàn truy cập; mục tiêu người dùng, AS-IS. |
| Tác nhân chính | Chủ trọ (A02); Nhân viên vận hành (A03); Người tìm phòng/người thuê (A04); Quản trị viên nền tảng (A05) |
| Tác nhân phối hợp | Không áp dụng |
| Mục tiêu nghiệp vụ | Thay mật khẩu sau khi xác minh mật khẩu hiện tại |
| Sự kiện kích hoạt | A02/A03 mở /settings/password; A04 có /tenant/password và đường Settings chung. A05 có quyền API nhưng chưa xác minh được điểm truy cập đổi mật khẩu dành riêng Admin trong UI [ROUTE, NAV, CTRL]. |
| Tiền điều kiện | Access JWT hợp lệ, User active/version/sid hợp lệ; STAFF profile/chủ trọ active. Người dùng biết mật khẩu hiện tại. Không yêu cầu capability admin/staff riêng hoặc mã MFA/step-up trong endpoint change-password [CTRL, JWT, SCOPE]. |
| Dữ liệu đầu vào và Validation | currentPassword string bắt buộc 1–128 ký tự; newPassword Chuỗi 12–128 ký tự, có ít nhất một chữ hoa A–Z, chữ thường a–z, chữ số 0–9 và ký tự ngoài A–Za–z0–9; không có kiểm tra lịch sử mật khẩu hoặc cấm trùng mật khẩu cũ [VAL].<br>UI chỉ kiểm current không rỗng, new tối thiểu 12; không có ô xác nhận trong TenantChangePasswordScreen. Backend vẫn kiểm đầy đủ policy kể cả UI cho qua [UI, VAL]. |
| Luồng thành công chính | B1 — Người dùng nhập mật khẩu hiện tại và mật khẩu mới, chọn Đổi mật khẩu; UI validate rồi SessionController gửi POST /api/v1/auth/change-password qua repository/API [UI, STATE, API].<br>B2 — JWT/DTO kiểm đầu vào; AuthService đọc User, kiểm active và argon2.verify currentPassword; băm newPassword [CTRL, JWT, VAL, SVC].<br>B3 — Hệ thống mở transaction, khóa User, đọc lại record và so current.passwordHash với hash đã đọc tại B2 để ngăn ghi đè thay đổi mật khẩu đồng thời [SVC].<br>B4 — Hệ thống cập nhật passwordHash, tăng sessionVersion một đơn vị và revokedAt cho mọi RefreshToken của user còn hiệu lực theo revokedAt=null; commit; API trả 204 [SVC, CTRL].<br>B5 — SessionController gọi logout để clear client; state unauthenticated. Mọi access JWT version cũ bị từ chối ở request tiếp theo; không cấp phiên mới trong response đổi mật khẩu [STATE, JWT].<br>B6 — Màn hình nếu còn mounted hiển thị SnackBar Đã đổi mật khẩu. Vui lòng đăng nhập lại.; router xử lý trạng thái unauthenticated trên route bảo vệ; kết thúc [UI, NAV]. |
| Luồng thay thế | A1 — Tại B2, newPassword bằng currentPassword nhưng vẫn đạt policy: không có kiểm khác nhau; service vẫn băm lại, tăng version/thu hồi refresh token, tiếp B3. Không tự thêm quy tắc cấm dùng lại mật khẩu [VAL, SVC]. |
| Luồng ngoại lệ | E1 — Tại B1, thiếu current hoặc new ít hơn 12 ký tự: UI hiển thị lỗi, không gửi; DB nguyên; người dùng sửa B1. Tại B2 nếu DTO sai (kể cả thiếu độ mạnh/max length), 400 VALIDATION_ERROR và details; UI banner ApiFailure.message; chưa ghi [UI, VAL, HTTP, ERR].<br>E2 — Tại B2, JWT invalid/expired/revoked/version mismatch hoặc STAFF inactive: 401 trước service. API client có xử lý refresh/401; nếu không khôi phục được thì UI nhận failure, không đổi password bởi request bị chặn [JWT, CLIENT].<br>E3 — Tại B2, password hiện tại sai/User không active/không tìm thấy: 401 INVALID_CREDENTIALS; UI hiển thị Email or password is incorrect. từ server dù đây là màn hình đổi mật khẩu, bỏ loading; không ghi, sửa B1 [SVC, UI].<br>E4 — Tại B3, passwordHash đã thay đổi giữa B2 và khóa User: 401 INVALID_CREDENTIALS; transaction hiện tại không commit đổi mật khẩu; thay đổi của request khác vẫn tồn tại; UI báo lỗi, kết thúc lần gửi [SVC].<br>E5 — Tại B3–B4, lỗi DB trong transaction: không commit password/version/token của transaction này; 500 INTERNAL_SERVER_ERROR nếu lỗi không ánh xạ. Nếu mất response sau commit thì kết quả client chưa xác định, không được suy mật khẩu cũ còn đúng [SVC, ERR].<br>E6 — Tại B5, logout/storage lỗi sau backend thành công: SessionController bắt lỗi logout, vẫn đặt unauthenticated; không hoàn tác password. Nếu storage.clear thất bại, chưa bảo đảm xóa secret vật lý. UI không có nhánh khôi phục mật khẩu cũ [STATE, STORE].<br>E7 — Tại B2, vượt limiter toàn cục mặc định 60/60 giây: 429 RATE_LIMITED, không chạy service; UI hiển thị message và cho sửa/gửi khi không loading [RATE, ERR, UI]. |
| Hậu điều kiện thành công | passwordHash mới đã lưu, sessionVersion tăng, mọi refresh token chưa revoked bị revoked. AuthSession không được update revokedAt trực tiếp nhưng các session version cũ không còn hợp lệ. Không tạo audit riêng trong changePassword, không tiêu thụ AccountAccessToken đang chờ ở service này [SVC, JWT]. |
| Bảo đảm tối thiểu khi thất bại | Sai mật khẩu/DTO/JWT không ghi nghiệp vụ. Transaction B3–B4 bao password/version/token; B5 dọn client ngoài transaction. Không bảo đảm session cục bộ xóa được khi storage lỗi, không bảo đảm AccountAccessToken cũ bị vô hiệu hóa bởi đổi mật khẩu [SVC, STORE]. |
| Quy tắc nghiệp vụ | BR-01 — Phải biết mật khẩu hiện tại; không đổi thay người khác vì userId từ JWT [CTRL, SVC].<br>BR-02 — Policy mới áp theo ChangePasswordDto, không theo validator UI tối thiểu 12 [VAL, UI].<br>BR-03 — Khóa User và so hash trước ghi để chống hai yêu cầu đổi password chồng nhau [SVC].<br>BR-04 — Đổi password luôn vô hiệu hóa tất cả phiên cũ bằng tăng version; không giữ phiên hiện tại [SVC, JWT].<br>BR-05 — Không kiểm lịch sử/cấm cùng password, không thu hồi AccountAccessToken trong hàm changePassword; không mô tả những bảo đảm này như AS-IS [SVC]. |
| Phân quyền và bảo mật | A02–A05 đều được gọi AuthGuard(jwt) endpoint của mình; không @Roles/capability/MFA/step-up ở handler. STAFF AuthController được interceptor cho qua. UI Admin chuyên dụng chưa có bằng chứng, không tự bỏ actor API khỏi Catalog [CTRL, JWT, SCOPE, NAV]. |
| Kết quả đầu ra | HTTP 204 không body, không token mới. UI unauthenticated và thông báo yêu cầu đăng nhập lại nếu còn mounted; việc phát SnackBar không được bảo đảm nếu router đã unmount [CTRL, STATE, UI]. |
| Quan hệ với Use Case khác | UC-SYS-06 dùng token khi quên mật khẩu; UC này cần JWT và mật khẩu cũ. Tái sử dụng logout UC-SYS-05.1 qua code không tự tạo include trong UML. UC-SYS-03 dùng password mới sau khi kết thúc [UML]. |
