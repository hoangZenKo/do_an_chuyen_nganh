# UC-SYS-05.1 — Đăng xuất phiên hiện tại

| Thuộc tính | Nội dung đặc tả |
|---|---|
| Mã Use Case | UC-SYS-05.1 |
| Tên Use Case | Đăng xuất phiên hiện tại |
| Mô tả nghiệp vụ | Người dùng rời phiên trên thiết bị hiện tại; ứng dụng cố gắng thu hồi phiên bằng refresh token rồi xóa credential cục bộ kể cả API mất kết nối [API, STORE, STATE]. Phải tách kết quả đăng xuất cục bộ và thu hồi backend. |
| Phạm vi và cấp độ | Hệ thống quản lý nhà trọ; G01 — Tài khoản và an toàn truy cập; mục tiêu người dùng, AS-IS. |
| Tác nhân chính | Chủ trọ (A02); Nhân viên vận hành (A03); Người tìm phòng/người thuê (A04); Quản trị viên nền tảng (A05) |
| Tác nhân phối hợp | Không áp dụng |
| Mục tiêu nghiệp vụ | Thu hồi phiên gắn refresh token và rời phiên cục bộ |
| Sự kiện kích hoạt | A02/A03 chọn Đăng xuất ở Settings; A04 chọn đăng xuất tại trang tài khoản/cổng người thuê; A05 chọn tại workspace quản trị; các điểm gọi chung SessionController.logout [UI, STATE]. |
| Tiền điều kiện | Có phiên đang dùng tại client theo ngữ cảnh Catalog. Endpoint logout thực tế công khai, không yêu cầu access JWT; để thu hồi backend phải có refresh token hợp lệ về kiểu/độ dài và khớp record. Nếu storage không còn session, ứng dụng vẫn chuyển unauthenticated mà không gọi API [CTRL, STORE, STATE]. |
| Dữ liệu đầu vào và Validation | refreshToken string bắt buộc, tối thiểu 32 ký tự; DTO không MaxLength. Ứng dụng lấy token trong secure storage, không hỏi người dùng nhập. Không nhận userId/role/sessionId từ body [VAL, STORE]. |
| Luồng thành công chính | B1 — Người dùng chọn đăng xuất; UI gọi SessionController.logout [UI, STATE].<br>B2 — Repository đọc session trong secure storage; có session thì AuthApi gửi POST /api/v1/auth/logout với refreshToken [STORE, API].<br>B3 — Hệ thống kiểm DTO/limiter 20/60 giây; SHA-256 raw token, tìm record và khóa User trong transaction [CTRL, VAL, SVC].<br>B4 — Nếu record gắn sessionId, hệ thống đặt revokedAt cho AuthSession chưa thu hồi của user đó và mọi RefreshToken chưa thu hồi có cùng sessionId; commit [SVC, DB].<br>B5 — API trả 204 không body; repository chạy storage.clear trong finally; SessionController đặt unauthenticated trong finally [CTRL, STORE, STATE].<br>B6 — Router áp authRedirect: route bảo vệ hiện tại chuyển login; trang discovery công khai có thể vẫn ở trang công khai. Kết thúc phiên cục bộ, không mặc định mọi nơi luôn redirect cùng một route [NAV]. |
| Luồng thay thế | A1 — Tại B2, storage không có session: không gọi backend; storage.clear vẫn chạy, state unauthenticated; đến B6. Không có thu hồi server mới [STORE, STATE].<br>A2 — Tại B3, token có độ dài hợp lệ nhưng không tìm thấy record: service return trong transaction, API vẫn 204; dữ liệu server không đổi; tiếp B5, không coi đây là lỗi token [SVC].<br>A3 — Tại B4, record legacy không có sessionId: chỉ thu hồi refresh token khớp tokenHash; không có AuthSession đích để thu hồi. Tiếp B5; access token legacy không có sid không bị logout riêng lẻ vô hiệu hóa qua session [SVC, JWT].<br>A4 — Tại B4, token/phiên đã revoked hoặc hết hạn nhưng record còn: không kiểm expiresAt để từ chối; các updateMany thu hồi record còn lại theo điều kiện; trả 204 và tiếp B5 [SVC]. |
| Luồng ngoại lệ | E1 — Tại B3, DTO sai hoặc quá 20/60 giây: API 400 VALIDATION_ERROR hoặc 429 RATE_LIMITED. AuthApi.logout nuốt DioException nên vẫn đến B5/B6; backend chưa chạy service ở request bị chặn, phiên server có thể còn hiệu lực [VAL, CTRL, API, ERR].<br>E2 — Tại B2–B5, network/HTTP lỗi: DioException bị bỏ qua, client vẫn xóa credential và unauthenticated; không có thông báo lỗi riêng từ AuthApi.logout. Không thể xác định đã thu hồi backend hay chưa nếu mất response, không có cơ chế retry server thu hồi ở đây [API, STORE, STATE].<br>E3 — Tại B2/B5, storage.read hoặc storage.clear ném lỗi không phải DioException: repository vẫn cố clear qua finally; SessionController vẫn chuyển unauthenticated qua finally nhưng lỗi có thể truyền về caller. Chưa xác minh được từ source code một thông báo UI chung cho mọi điểm gọi; nếu clear thất bại không bảo đảm secret đã xóa vật lý [STORE, STATE]. |
| Hậu điều kiện thành công | Client không còn credential nếu storage.clear thành công và state unauthenticated. Ở nhánh B4 có sessionId, phiên backend bị revoked nên JWT sid đó bị từ chối tại lần dùng kế tiếp; các phiên thiết bị khác không bị thu hồi [SVC, JWT, STORE, STATE]. |
| Bảo đảm tối thiểu khi thất bại | finally bảo đảm đã gọi storage.clear và đặt state unauthenticated, không bảo đảm thao tác storage luôn thành công. Không có liên transaction giữa thu hồi backend và xóa client; offline logout không chứng minh server session bị thu hồi. Transaction backend chỉ bao các thay đổi token/session của service [SVC, STORE, STATE]. |
| Quy tắc nghiệp vụ | BR-01 — Thu hồi theo hash token; backend không nhận userId để chọn tài khoản khác [SVC, VAL].<br>BR-02 — Token gắn sid thu hồi toàn bộ refresh token cùng session, kể cả raw token cũ đã rotate; không thu hồi mọi phiên User [SVC].<br>BR-03 — Token không tồn tại vẫn 204; logout không kiểm password hoặc access JWT [CTRL, SVC].<br>BR-04 — Xóa client không phụ thuộc network; không thay sessionVersion ở logout [SVC, API, STORE]. |
| Phân quyền và bảo mật | Actor Catalog A02/A03/A04/A05 đại diện người đang rời phiên; quyền kỹ thuật API dựa việc nắm refresh token, không có JWT/@Roles. Không mô tả E401 do access JWT hết hạn tại endpoint công khai này. Phiên sid đã thu hồi bị JwtStrategy từ chối; token legacy thiếu sid có giới hạn A3 [CTRL, JWT]. |
| Kết quả đầu ra | 204 No Content từ server nếu request đến service và hoàn thành; không trả revoked count. UI state unauthenticated, redirect tùy route; network fail có thể vẫn hoàn tất đăng xuất cục bộ [CTRL, STATE, NAV]. |
| Quan hệ với Use Case khác | Khác UC-SYS-05.2: UC này rời client hiện tại, UC kia chủ động tra/thu hồi phiên từ tài khoản. UC-SYS-07 và UC-SYS-10 gọi logout để dọn client sau đổi mật khẩu; lời gọi tái sử dụng không tự thêm include vào UML [STATE, UML]. |
