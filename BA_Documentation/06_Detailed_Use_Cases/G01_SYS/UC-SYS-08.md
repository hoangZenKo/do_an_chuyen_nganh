# UC-SYS-08 — Kích hoạt tài khoản người thuê từ lời mời

| Thuộc tính | Nội dung đặc tả |
|---|---|
| Mã Use Case | UC-SYS-08 |
| Tên Use Case | Kích hoạt tài khoản người thuê từ lời mời |
| Mô tả nghiệp vụ | Người nhận mã mời người thuê đặt mật khẩu; hệ thống tạo User TENANT và liên kết với hồ sơ Tenant có sẵn, đánh dấu lời mời đã nhận rồi cấp phiên. Không tự tạo hợp đồng hoặc hóa đơn [SVC]. |
| Phạm vi và cấp độ | Hệ thống quản lý nhà trọ; G01 — Tài khoản và an toàn truy cập; mục tiêu người dùng, AS-IS. |
| Tác nhân chính | Khách/chưa đăng nhập (A01) |
| Tác nhân phối hợp | Không áp dụng |
| Mục tiêu nghiệp vụ | Nhận quyền vào cổng người thuê, gắn đúng hồ sơ đã được chủ trọ mời. |
| Sự kiện kích hoạt | A01 mở /tenant/activate?code=... hoặc nhập mã mời trên màn hình Kích hoạt tenant và chọn Kích hoạt [UI, ROUTE]. |
| Tiền điều kiện | Lời mời TenantInvite khớp mã, chưa acceptedAt/chưa hết hạn; Tenant active, chưa có userId; chủ trọ active; email lời mời chưa bị User khác chiếm. Không cần JWT hoặc password trước đó [SVC, DB]. |
| Dữ liệu đầu vào và Validation | inviteCode string bắt buộc 16–256 ký tự; UI trim và chỉ kiểm không rỗng, có thể lấy initialCode từ query code [UI, VAL, ROUTE].<br>password Chuỗi 12–128 ký tự, có ít nhất một chữ hoa A–Z, chữ thường a–z, chữ số 0–9 và ký tự ngoài A–Za–z0–9; không có kiểm tra lịch sử mật khẩu hoặc cấm trùng mật khẩu cũ [VAL].<br>UI chỉ kiểm password ít nhất 12 ký tự, không có ô confirm; DTO vẫn enforce độ mạnh và max 128. Không gửi email/fullName/phone/role/permissions/propertyIds; hệ thống lấy từ lời mời và Tenant [VAL, SVC]. |
| Luồng thành công chính | B1 — A01 mở màn hình kích hoạt; UI nạp code từ query nếu có hoặc cho nhập mã, nhận password mới; người nhận chọn Kích hoạt [UI, ROUTE].<br>B2 — UI validate, đặt loading, SessionController gọi API POST /api/v1/tenant-invites/accept với inviteCode đã trim và password; backend áp DTO và limiter toàn cục [UI, API, VAL, RATE].<br>B3 — Hệ thống SHA-256 inviteCode để tìm TenantInvite; khi tìm được thì khóa Tenant và đọc lại lời mời trong transaction. Kiểm chưa nhận/chưa hết hạn/Tenant active/chưa gắn User và chủ trọ active [SVC].<br>B4 — Hệ thống băm password argon2 và tạo User TENANT với fullName/phone lấy từ Tenant, email lấy từ TenantInvite [SVC, DB-U].<br>B5 — Trong cùng transaction, hệ thống cập nhật Tenant.userId bằng User vừa tạo; không thay đổi Lease/Invoice [SVC, DB].<br>B6 — Hệ thống ghi acceptedAt cho lời mời và commit transaction; sau đó gọi AuthService.issueSession ở ngoài transaction kích hoạt [SVC, SESSION].<br>B7 — API trả User/token và hạn dùng; repository kiểm role hỗ trợ và lưu secure storage, SessionController authenticated [API, STORE, STATE].<br>B8 — UI điều hướng homeRouteForSession: /explore cho role TENANT, không mặc định /tenant dù đã gắn hồ sơ thuê; kết thúc [UI, NAV]. |
| Luồng thay thế | Không áp dụng |
| Luồng ngoại lệ | E1 — Tại B2, UI thiếu code hoặc password ít hơn 12: lỗi cạnh field, không gửi và không ghi; sửa B1. Nếu API DTO sai (code 16–256, policy password, unknown field), 400 VALIDATION_ERROR; UI hiển thị ApiFailure.message, bỏ loading; sửa B1 [UI, VAL, HTTP, ERR].<br>E2 — Tại B3, mã không tồn tại/đã dùng/hết hạn hoặc Tenant đã gắn User/inactive hoặc chủ trọ inactive: 401 INVALID_TENANT_INVITE, message Tenant invite is invalid or expired.; transaction không tạo tài khoản mới. UI banner message, quay form nhưng không hứa cùng mã có thể dùng lại; cần mã còn hợp lệ [SVC, UI].<br>E3 — Tại B4, email trùng theo unique User.email: Prisma P2002 được service ánh xạ 409 EMAIL_ALREADY_REGISTERED. Transaction kích hoạt không commit User/Tenant.userId/acceptedAt; UI hiển thị Email is already registered., không tự nối User sẵn có; kết thúc lần gửi [SVC, DB-U, UI].<br>E4 — Tại B2, limiter mặc định 60/60 giây: 429 RATE_LIMITED, chưa chạy service, UI hiển thị ApiFailure.message; không mutation bởi request này [RATE, ERR, UI].<br>E5 — Tại B6–B8, lỗi cấp phiên/ký JWT/storage/mạng sau transaction kích hoạt: UI banner lỗi, loading=false; User và acceptedAt có thể đã commit cùng Tenant.userId, mã không còn dùng lại. Không hoàn tác kích hoạt để đáp ứng response thất bại; đăng nhập sau đó là mục tiêu UC-SYS-03 [SVC, SESSION, STORE, UI].<br>E6 — Tại B3–B6, lỗi DB không ánh xạ: filter 500 INTERNAL_SERVER_ERROR; nếu phát sinh trong transaction kích hoạt thì transaction đó không commit; không mở rộng bảo đảm này sang issueSession/các bước client ngoài transaction [SVC, ERR]. |
| Hậu điều kiện thành công | User TENANT active, Tenant.userId liên kết user đó duy nhất, acceptedAt được lưu cùng transaction; User không có quyền chủ trọ. Session backend/client cấp nếu B7 thành công; hợp đồng/phòng/hóa đơn giữ nguyên bởi accept [SVC, DB]. |
| Bảo đảm tối thiểu khi thất bại | Transaction kích hoạt bao tạo User/link Tenant/acceptedAt; không bao issueSession và storage. Lỗi trước commit không để lại nhóm ghi đó; lỗi sau commit có thể để lại tài khoản đã kích hoạt, mã đã dùng nhưng chưa có phiên client. Không tự sinh lời mời mới hoặc gửi email trong accept [SVC, SESSION, STORE]. |
| Quy tắc nghiệp vụ | BR-01 — Mã raw chỉ được băm SHA-256 để tra tokenHash unique; lời mời tạo trước đó mặc định 7 ngày, khác AccountAccessToken 30 phút [SVC, DB].<br>BR-02 — Role và thông tin liên kết hồ sơ chỉ lấy từ dữ liệu đã lưu, không body accept [SVC, VAL].<br>BR-03 — Khóa Tenant và đọc lại ngăn nhận hai lần; email unique vẫn bảo vệ đua giữa các lời mời [SVC, DB-U].<br>BR-04 — Không dùng chung email đã có User, không tự chuyển tài khoản TENANT tìm phòng thành User gắn Tenant trong accept [SVC].<br>BR-05 — Tenant active và chưa có userId; chỉ nối đúng Tenant của mã, không tìm người thuê chỉ theo số điện thoại hoặc email. [SVC, DB]. |
| Phân quyền và bảo mật | A01 là người nắm mã mời; API accept không @Roles/JWT. Kiểm trạng thái lời mời/chủ trọ và Tenant nằm service, không thể nhận thay chỉ bằng tenantId/staffId [CTRL, SVC]. Sau cấp phiên, STAFF chịu JWT profile/owner và permission/scope ở các nghiệp vụ khác; TENANT không đồng nghĩa quyền LANDLORD [JWT, SCOPE]. Không thêm E01 giao email vào accept: endpoint chỉ đổi mã sẵn có, không gọi provider [SVC]. |
| Kết quả đầu ra | POST mặc định HTTP 201; data {user,accessToken,refreshToken,accessTokenExpiresAt,refreshTokenExpiresAt}; role response tenant. Điều hướng B8 [CTRL, SESSION, NAV]. |
| Quan hệ với Use Case khác | Khác UC-SYS-10: UC này tạo User và nối Tenant từ TenantInvite và tự cấp phiên; UC-SYS-10 đổi mật khẩu User đã có bằng AccountAccessToken và yêu cầu đăng nhập lại. Tạo/gửi lời mời thuộc UC khác, không tự thêm include/extend vào sơ đồ G01 [UML]. |
